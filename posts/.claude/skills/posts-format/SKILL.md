# posts/ 格式規範

## 結構：一個主題一個資料夾

```
posts/
  YYYYMMDD_主題/
    企劃.md          # 規劃：主題、讀者、起承轉合、查證、時程
    <平台>.md        # 成品，一個平台一個檔：discord.md
    文案.md          # 只留文案的主題（設計稿在別處，例如 Canva）用這個名字
    photos/          # 這個主題的圖片，編號從 01 開始
```

- 資料夾名稱格式：`YYYYMMDD_主題`，例：`20261016_磨石地板`、`20261026_高雄プチ旅行`
- 主題是單純的名詞，**不加括號、引號或「」**；中文或日文都可以
- 平台檔名用小寫英文（`discord.md`、`ig-story.md`），一眼看出發在哪裡
- 一個主題不一定四種檔案都有：有企劃的主題用 `企劃.md` + `<平台>.md`；只有文案的主題只放 `文案.md`
- 圖片放在該主題自己的 `photos/`，編號只在該主題內計算
  - 檔名 `NN名稱.副檔名`，名稱用小寫英文加底線，例：`01notch_taipei.jpeg`、`01taiwan_dishes.jpg`
  - 副檔名照原檔（`.jpg`、`.jpeg` 都有），不要為了統一而轉檔
  - 剛從手機匯入的 `IMG_xxxx.jpg` 是暫時狀態，用在文中之前先改成 `NN名稱`

## 標題與資料夾同步

- 檔案的 `#`（H1）格式：`YYYY-MM-DD | 主題` + 角色，主題和角色之間**沒有空格**，只有 `Discord` 這類英文平台名前面留一個空格。例：
  - 企劃：`# 2026-10-16 | 磨石地板企劃`
  - 文案：`# 2026-10-17 | 台灣小吃文案`
  - 平台成品：`# 2026-10-16 | 磨石地板 Discord`
- H1 的「主題」部分與資料夾名稱的主題**逐字一致**，日期是同一天，只是寫法不同：H1 用 `YYYY-MM-DD | `，資料夾用 `YYYYMMDD_`。
- 同一個資料夾裡每個檔案的 H1 都要帶角色（企劃／文案／平台名），不要只寫主題。
- 改資料夾名時，裡面所有檔案的 H1 一起改，不可只改一邊。
- 改名、搬檔用 `git mv`。

## 成品檔（`<平台>.md`、`文案.md`）

### 開頭的 HTML 註解

H1 之前放 HTML 註解，不會發出去：

1. **用法說明**（必有）：這個檔案給哪個平台用、怎麼分段、哪些行不要發。例：
   - Discord：`<!-- Discord 投稿用。以「---」為界，一則訊息一則訊息分開發。🖼️ 的行是圖片指示，不要發出去 -->`
   - Instagram story：`<!-- Instagram story 用。這份是畫面上的文字貼圖文案，盡量短。🖼️ 的行是圖片指示，不要發出去 -->`
2. **稿件狀態**（草稿期間才有）：`<!-- 初稿（Claude 代寫，YYYY-MM-DD）。待確認：… -->`
   - 「待確認」列出還沒查證的事實、拿不準的日文用法，用 `／` 分隔
   - 使用者改完、確認完之後，把這行拿掉或更新

### 內文區塊

用二級標題分區，內容依檔案種類而定：

- `discord.md`：`## 標題`（一行，吸引點進來的問句）、`## 文稿`
- `文案.md`：`## 製作分工`（誰寫文案、設計稿在哪，附 Canva 連結）、`## 文稿`、`## 標語候選`（用三級標題依方向分組，例：日常感、互動、旅行的行動呼籲）
- 平台檔案只放要發的東西；來源、查證、取捨留在 `企劃.md`

### 文稿的寫法

- 圖片指示獨立一行：`🖼️ 図N：說明(`檔名`)`。成品裡用日文的「図」，企劃裡用中文的「圖」，兩邊編號要對得上。檔名可省略 `photos/`，在 `文案.md` 寫 `photos/` 路徑也可以，但同一個檔案內要一致
- 圖與文放在同一則：圖在上、文在下
- Discord 用單獨一行 `---` 分則，一則訊息 2,000 字以內
- 一句一行，不用空行硬隔，段落之間才空行
- 文稿語言依該專案決定（磨石地板是日文常體，不用敬語）

## 企劃檔（`企劃.md`）

H1 之後用二級標題，順序如下，沒有內容的區塊可以先不放：

1. `## 主題與核心訊息`：一句話（讀完要記住什麼）、角度、字數上限（含目前字數現況）
2. `## 讀者與頻道`：平台與頻道、讀者（分角色列）、語言與文體、日文用語、互動期待
3. `## 文章前後關係（起承轉合）`：起／承／轉／合各一個三級標題，標題寫成 `### 起｜這段在做什麼`。每段固定欄位：
   - 內容、關鍵字
   - 圖（沒有就寫「無」）
   - 這段要說的一句話
   - 要查證
   - 字數／訊息數
   - 字數限制下的取捨（有取捨才寫）
4. `## 查證清單`：表格，欄位 `項目｜查到的內容｜來源｜狀態`。來源要附連結與日期；狀態寫「已查」「未確認」「待問店家」這類，沒查過的不要寫進文稿
5. `## 圖片清單`：表格，欄位 `圖號｜內容｜來源／授權｜備註`
6. `## Discord 版面`（或其他平台）：每則字數上限、圖文順序，以及每則對應哪幾段、哪張圖、預估字數的表格（有合計）
7. `## 結尾互動`：原本的問題、改成雙向後各讀者的問法
8. `## 時程與狀態`：表格，欄位 `項目｜日期｜狀態`，至少列企劃、查證、主文草稿、發文；暫定的日期後面加「（暫定）」

其他規則：

- 還不確定的地方用 HTML 註解標 `<!-- 待確認：… -->`，不要直接改寫內容
- 剛開好的主題可以只有 H1（例：`20261026_高雄プチ旅行`），內容之後再補，但 H1 仍要照上面的格式
