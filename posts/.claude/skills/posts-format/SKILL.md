# posts/ 格式規範

## 語言原則

- 這份規範本身（說明文）用繁體中文，因為是 meta 層級的規則。
- **posts/ 底下的 Markdown 檔案，全部用日文寫（包含 `#`（H1））**：標題、表格欄位名稱、固定欄位、HTML 註解、狀態詞、內文都是日文。這是為了讓使用者在整理過程中也持續用日文，而且 H1 不再混用中文漢字，避免看起來分不清。
- 角色用語用日文漢字：`企画`（不是繁體中文的「企劃」）、`文案`。H1 格式見「標題與資料夾同步」。檔名也用同一個字：`企画.md`。
- 檔名和資料夾名稱也全部用日文（`企画.md`、`文案.md`、`ディスコード.md`、`写真/`）。例外只有專有名詞本身（H1 裡的 `Discord`）。
- 以前的主題（例：`20261016_テラゾーの床`）的標題、欄位名稱、狀態詞已經改成日文版面，但內文裡中文寫的說明（查證內容、備註等）還沒翻。之後動到哪份，再順便改成日文（要先跟使用者說一聲）。

## 結構：一個主題一個資料夾

```
posts/
  YYYYMMDD_主題/
    企画.md          # 規劃：主題、讀者、起承轉合、查證、時程
    <平台>.md        # 成品，一個平台一個檔：ディスコード.md
    文案.md          # 只留文案的主題（設計稿在別處，例如 Canva）用這個名字
    写真/            # 這個主題要用的完成圖片，編號從 01 開始
    素材/            # 拍攝時的原圖、加工前的材料（需要加工時才有，不放進成品）
```

- 資料夾名稱格式：`YYYYMMDD_主題`，例：`20261016_テラゾーの床`、`20261026_高雄プチ旅行`
- 主題是單純的名詞，**不加括號、引號或「」**；中文或日文都可以
- 平台檔名用日文片假名（`ディスコード.md`、`インスタストーリー.md`），一眼看出發在哪裡
- 一個主題不一定四種檔案都有：有企画的主題用 `企画.md` + `<平台>.md`；只有文案的主題只放 `文案.md`
- 圖片放在該主題自己的 `写真/`，編號只在該主題內計算
  - 檔名 `NN名稱.副檔名`，名稱用日文，不加空白（要分詞用底線），例：`01ノッチ店内.jpeg`、`01台湾グルメ三品.jpg`。同一個圖號有多個材料時，名稱要能區分（例：`01キチンキーウ全体.jpg`、`01キチンキーウ断面.jpg`）
  - 副檔名照原檔（`.jpg`、`.jpeg` 都有），不要為了統一而轉檔
  - 剛從手機匯入的 `IMG_xxxx.jpg` 是暫時狀態，用在文中之前先改成 `NN名稱`
  - 編號對應企画／成品裡的圖號（図1 → `01…`）。需要合成或裁切的圖，材料原圖先留著，完成後再整理

## 標題與資料夾同步

- 檔案的 `#`（H1）格式：`YYYY-MM-DD | 主題` + 角色，主題和角色之間**沒有空格**，只有 `Discord` 這類英文平台名前面留一個空格。例：
  - 企画：`# 2026-10-16 | テラゾーの床企画`
  - 文案：`# 2026-10-17 | 台湾グルメ文案`
  - 平台成品：`# 2026-10-16 | テラゾーの床 Discord`
  - 角色一律用日文漢字（`企画`，不是繁體中文的「企劃」），和檔名 `企画.md` 同字形
- H1 的「主題」部分與資料夾名稱的主題**逐字一致**，日期是同一天，只是寫法不同：H1 用 `YYYY-MM-DD | `，資料夾用 `YYYYMMDD_`。
- 同一個資料夾裡每個檔案的 H1 都要帶角色（企画／文案／平台名），不要只寫主題。
- 改資料夾名時，裡面所有檔案的 H1 一起改，不可只改一邊。
- 改名、搬檔用 `git mv`。

## 成品檔（`<平台>.md`、`文案.md`）

### 開頭的 HTML 註解

H1 之前放 HTML 註解，不會發出去（註解內容用日文）：

1. **用法說明**（必有）：這個檔案給哪個平台用、怎麼分段、哪些行不要發。例：
   - Discord：`<!-- Discord投稿用。「---」で区切って、1メッセージずつ分けて投稿する。🖼️の行は画像の指示なので、投稿しない -->`
   - Instagram story：`<!-- Instagram story用。画面に載せるテキストスタンプの文案。できるだけ短く。🖼️の行は画像の指示なので、投稿しない -->`
2. **稿件狀態**（草稿期間才有）：`<!-- 初稿（Claude代筆、YYYY-MM-DD）。要確認：… -->`
   - 「要確認」列出還沒查證的事實、拿不準的日文用法，用 `／` 分隔
   - 使用者改完、確認完之後，把這行拿掉或更新

### 內文區塊

用二級標題分區，內容依檔案種類而定：

- `ディスコード.md`：`## タイトル`（一行，吸引點進來的問句）、`## 本文`
- `文案.md`：`## 制作分担`（誰寫文案、設計稿在哪，附 Canva 連結）、`## 本文`、`## タグライン候補`（用三級標題依方向分組，例：日常感、やりとり、旅行への呼びかけ）
- 平台檔案只放要發的東西；來源、查證、取捨留在 `企画.md`

### 文稿的寫法

- 圖片指示獨立一行：`🖼️ 図N：説明(`ファイル名`)`。企画和成品都用日文的「図」，兩邊編號要對得上。檔名可省略 `写真/`，在 `文案.md` 寫 `写真/` 路徑也可以，但同一個檔案內要一致
- 圖與文放在同一則：圖在上、文在下
- Discord 用單獨一行 `---` 分則，一則訊息 2,000 字以內
- 一句一行，不用空行硬隔，段落之間才空行
- 文稿語言依該專案決定（テラゾーの床是日文常體，不用敬語）

## 企画檔（`企画.md`）

H1 之後用二級標題，順序如下，沒有內容的區塊可以先不放。標題、欄位名稱、狀態詞全部用日文：

1. `## テーマとコアメッセージ`：一句話（讀完要記住什麼）、角度、字數上限（含目前字數現況）
2. `## 読者とチャンネル`：平台與頻道、讀者（分角色列）、語言與文體、日文用語、互動期待
3. `## 文章の流れ（起承転合）`：起／承／轉／合各一個三級標題，標題寫成 `### 起｜この段で何をするか`（承、転、合也同樣）。每段固定欄位：
   - 内容、キーワード
   - 画像（沒有就寫「なし」）
   - この段で言う一言
   - 要調査
   - 文字数／メッセージ数
   - 文字数制限での取捨（有取捨才寫）
4. `## 調査リスト`：表格，欄位 `項目｜調べた内容｜出典｜状態`。來源要附連結與日期；狀態寫「確認済み」「未確認」「お店に確認待ち」這類，沒查過的不要寫進文稿
5. `## 画像リスト`：表格，欄位 `図番号｜内容｜出典・権利｜備考`。圖片需要加工（合成、裁切）時，在備考寫清楚用哪個檔案、做什麼
6. `## Discordレイアウト`（或其他平台，例：`## Instagramレイアウト`）：每則字數上限、圖文順序，以及每則對應哪幾段、哪張圖、預估字數的表格（有合計）
7. `## 締めのやりとり`：原本的問題、改成雙向後各讀者的問法
8. `## スケジュールと状況`：表格，欄位 `項目｜日付｜状況`，至少列企画、查證（調査）、主文草稿、發文（投稿）；暫定的日期後面加「（暫定）」
9. 需要時另加作業用區塊（例：`## Canva作業`），放在上面各區塊之後

其他規則：

- 還不確定的地方用 HTML 註解標 `<!-- 要確認：… -->`，不要直接改寫內容
- 剛開好的主題可以只有 H1（例：`20261026_高雄プチ旅行`），內容之後再補，但 H1 仍要照上面的格式
